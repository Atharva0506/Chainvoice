## Architecture Decisions
1. **Multi-Variant Djed Routing**: Introduce a `DjedVariantRouter` abstraction layer. Configuration-first approach for adding variants (Classic, Wren) without code rewrites. Preserves native + ERC-20 path compatibility.
2. **Privacy Reliability Path**: Replace or fix the broken Lit Protocol integration via mentor-guided direction (ECIES with on-chain key registry, Waku, or hybrid fallback). Must preserve compatibility with the existing `encryptedInvoiceData` field.
3. **Chainvoice × StablePay Bridge**: Use `invoiceId` as the shared key. Chainvoice acts as the invoice state source of truth; StablePay handles settlement.
4. **Bridge Security**: Implement a caller whitelist on `InvoiceManager` so only the deployed `PaymentRouter` can trigger the `markPaid` callback.
5. **Decentralized Analytics**: No subgraphs or server. Client-side projection using ethers.js event queries (e.g., `PaymentSettled`) fed into lightweight in-memory React reducers.

## Key Modules
- `privacy/`: Mentor-guided reliability path adapters and key helpers (ECIES/Lit).
- `invoice/`: Schema normalization, invoice lifecycle management, and state projection.
- `payments/`: Variant preflight, Djed routing, and settlement orchestration.
- `bridge/`: Deep-link generation and callback utilities for `invoiceId` state synchronization.
- `analytics/`: Metric calculators and chart view models (aging buckets, settlement ratio, etc.).
- *(Stretch Goal)* `@stabilitynexus/chainvoice-sdk`: Typed npm package for invoice flows.

## Important Constraints and Risks
- **Backward Compatibility**: Existing encrypted invoices must remain readable; no forced migration for old invoices. Token-path regressions are unacceptable.
- **Small, Reviewable PRs**: No "big-bang" replacements. Ship in mergeable milestones with explicit tests and rollback-safe increments.
- **Testing Requirements**: Comprehensive tests required (Foundry/Hardhat for contracts, Jest for frontend utilities).
- **Concurrency/Race Conditions**: `markPaid` must be idempotent to handle potential duplicate `PaymentSettled` events securely.
